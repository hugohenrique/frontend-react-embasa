Etapa 3 do ciclo

  
Conceito

  
O React redesenha quando o estado muda.







  
Eventos: on + o que aconteceu

  

  
O mesmo addEventListener do encontro 3, escrito direto na tag: onClick, onChange, onSubmit.







  
Passe a função, não a chamada

  

    
Certo
“Quando clicarem, rode isto.”

    
Errado
Roda na hora de desenhar, não no clique.

  







  
Desenhar é chamar a função

  

    
React chama App()
›
    
App devolve JSX
›
    
React atualiza a tela

  

  
Para a tela mudar, o React precisa chamar a função de novo. E ele só chama de novo quando alguém avisa que algo mudou.







  
Por que o let não funciona

  

    
Ninguém avisa o React
Mudar uma variável é silencioso. O React não fica olhando as variáveis.

    
E ela renasce
Se a função rodasse de novo, a primeira linha faria let filtro = "todas" outra vez.

  







  
useState: um valor que o React guarda

  

  

    
tentativas
O valor de agora.

    
setTentativas
Troca o valor e avisa o React.

    
useState(0)
O valor inicial, só na primeira vez.

Tela atualizada

Ainda no conceito

  
Imutabilidade

  
Estado não se altera: se substitui.







  
Troque, não altere

  

    
Alterar
Mesma lista. O React compara, acha igual e não redesenha.

    
Substituir
Lista nova, com os itens antigos e o novo. O React vê a diferença.

  







  
Boa prática ou não? Responda no chat

  

    
1onClick={() => tentativas++}

4horarios.push("10h"); setHorarios(horarios);

  







  
As respostas

  

    
1 · ruimtentativas é const: o TypeScript nem deixa. E alterar sem o set não avisa o React.

    
2 · ruimChama na hora de desenhar, que desenha de novo, que chama de novo: “Too many re-renders”.

    
3 · boaUm valor novo, pelo set, dentro de uma função.

    
4 · ruimMesma lista alterada. A tela não muda. O certo: setHorarios([...horarios, "10h"]).
