Guia do ambiente de desenvolvimento

Segunda-feira, 9 de novembro de 2026. Vamos montar o ambiente juntos, ao vivo, na primeira parte da aula. Este guia é o mesmo roteiro, por escrito, para você consultar durante e depois.

O que vamos instalarNode.js (versão LTS) e Visual Studio Code. Só isso. O resto vem pelo npm, dentro do projeto.
O que você precisaComputador com Windows 10 ou 11, internet e cerca de 1 GB livre. O navegador do curso é o Chrome (o Edge também serve).
Antes da aula, se puderBaixe os dois instaladores (passos 1 e 2). Não precisa instalar: instalamos juntos.

Em cada passo, você encontra três coisas: por que usamos aquilo, como fazer e como saber que deu certo. Se algo sair diferente, abra o quadro vermelho “Se der erro” daquele passo. Se ainda assim não funcionar, mande no grupo do WhatsApp um print da tela com a mensagem de erro. À tarde, tiramos as dúvidas.

1Node.js, na versão LTS

Até a sexta, o JavaScript rodava só dentro do navegador. O Node.js faz o JavaScript rodar no seu computador, fora do navegador. As ferramentas modernas de front-end (o Vite, o compilador do TypeScript, o verificador de código) são programas escritos em JavaScript, então precisam do Node para funcionar. Junto com o Node vem o npm, que baixa essas ferramentas e as bibliotecas, como o próprio React.

LTS quer dizer Long Term Support, suporte de longo prazo. É a versão estável, que recebe correções por anos. Hoje é o Node.js 26, LTS desde 28 de outubro de 2026, com suporte até abril de 2029. O site também oferece a versão Current, com novidades ainda em teste: para trabalho, sempre a LTS.
  1. Abra nodejs.org/pt-br/download no Chrome.
  2. Confira que está selecionada a versão marcada como LTS (hoje, a v26), para Windows, e baixe o Instalador Windows (.msi).
  3. Abra o arquivo baixado e avance com Next, aceitando a licença e a pasta sugerida.
  4. Na tela Tools for Native Modules, deixe a caixa desmarcada e avance.
    Essa opção instala Python e ferramentas de compilação do Windows, para bibliotecas escritas em C++. Não usamos nada disso no curso, e ela demora bastante.
  5. Clique em Install. Se o Windows perguntar se permite alterações, confirme.

Conferir a instalação

Abra o Prompt de Comando: tecla Windows, digite cmd e aperte Enter. Precisa ser uma janela nova, aberta depois da instalação. Digite os dois comandos, um de cada vez:

node -v
npm -v
O primeiro mostra uma versão começando com v26. (por exemplo, v26.13.0) e o segundo mostra um número de versão do npm. Durante a aula, escreva no chat a versão do Node que apareceu.
Se der erro no passo 1

“'node' não é reconhecido como um comando interno ou externo”: a janela do terminal foi aberta antes da instalação. Feche todas as janelas de terminal e abra uma nova. Se continuar, reinicie o computador.

Apareceu uma versão menor que 22 (por exemplo, v18.): já havia um Node antigo instalado. O projeto exige no mínimo a 22.12. Instale a LTS por cima: o instalador substitui a versão anterior.

Apareceu v22 ou v24: funciona com o curso. Se puder, atualize para a 26, para ficarmos todos iguais.

O Windows pede senha de administrador e você não tem: siga o plano B, sem administrador.

2Visual Studio Code

Até agora, escrevíamos no navegador, no laboratório. A partir de hoje, o código fica em arquivos no seu computador, e precisamos de um editor de verdade. O VS Code é gratuito, é o editor mais usado em front-end e entende TypeScript sem instalar nada: é a mesma empresa que faz os dois, e ele usa o próprio TypeScript para sublinhar erros enquanto você digita, como no laboratório. Ele também tem um terminal embutido, então fazemos tudo numa janela só.
  1. Abra code.visualstudio.com/download e baixe a versão para Windows, no botão principal. Ela é a User Installer, que instala só para o seu usuário e normalmente não pede administrador.
  2. No instalador, aceite a licença e avance. Na tela Tarefas adicionais, marque:
    • Adicionar a ação “Abrir com Code” ao menu de contexto de pasta: para abrir uma pasta clicando com o botão direito;
    • Adicionar em PATH (normalmente já vem marcada): para abrir o VS Code pelo terminal, com o comando code.
  3. Termine a instalação e abra o VS Code.

Uma configuração: o terminal

No VS Code, aperte Ctrl + Shift + P, digite Terminal: Select Default Profile e escolha Command Prompt.

O terminal padrão do VS Code no Windows é o PowerShell, que em muitos computadores bloqueia os scripts do npm com o erro “a execução de scripts foi desabilitada neste sistema”. O Prompt de Comando não tem essa trava, e todos os comandos do curso funcionam igual nele. Assim, a sua tela fica igual à de todo mundo.

Se der erro no passo 2

O instalador pede administrador: confira se baixou a User Installer (o nome do arquivo começa com VSCodeUserSetup). Se a TI bloquear qualquer instalação, há a versão .zip na mesma página de download: descompacte numa pasta sua e abra o Code.exe.

Não encontro “Command Prompt” na lista: digite só Select Default Profile. Se os menus estiverem em português, a opção chama Prompt de Comando.

3Criar o projeto React com TypeScript

Um projeto React precisa de várias peças conversando: o React, o TypeScript, um servidor local e algo que transforme o nosso código em JavaScript que o navegador entende. Montar isso à mão levaria horas. O Vite é a ferramenta que cria o projeto com tudo configurado e depois roda o servidor local. É hoje o caminho mais usado para começar um projeto React, rápido e com poucas configurações. Lembram, no encontro 3, que módulos de JavaScript não funcionavam abrindo o arquivo com dois cliques, porque precisavam de um servidor? O Vite é esse servidor.

Uma pasta para o curso

Crie uma pasta chamada curso-react dentro da sua pasta de usuário, por exemplo C:\Users\seu.nome\curso-react. Depois, no VS Code: File > Open Folder (ou Arquivo > Abrir Pasta) e escolha essa pasta.

Evite a pasta Documentos e a Área de Trabalho quando elas estiverem no OneDrive: o projeto vai ter milhares de arquivos pequenos, e a sincronização deixa tudo lento ou trava arquivos. Evite também espaços e acentos no caminho, que algumas ferramentas não aceitam bem.

Se o VS Code perguntar “Do you trust the authors of the files in this folder?”, clique em Yes, I trust the authors. A pasta é sua; sem isso, o editor desliga parte dos recursos.

Gerar o projeto

Abra o terminal do VS Code com Ctrl + ' (a tecla de aspas simples, ao lado do Enter; no menu: Terminal > New Terminal). Copie e cole o comando abaixo, inteiro, numa linha só:

npx create-vite@9.3.4 central-de-solicitacoes --template react-ts --no-eslint --no-immediate

Se aparecer Need to install the following packages: create-vite@9.3.4 Ok to proceed? (y), digite y e Enter.

Parte do comandoO que faz
npxRoda uma ferramenta do npm sem instalá-la de vez no computador. Ela é baixada, usada e pronto.
create-vite@9.3.4O criador de projetos do Vite. Fixamos a versão para que todos recebam exatamente os mesmos arquivos do material.
central-de-solicitacoesO nome do projeto e da pasta que será criada.

Abrir o projeto como pasta principal

No terminal, digite:

code central-de-solicitacoes

Abre uma janela nova do VS Code, já na pasta do projeto. Feche a janela antiga e trabalhe nesta. Se o comando code não funcionar, use File > Open Folder e escolha a pasta central-de-solicitacoes.

O VS Code procura as configurações do TypeScript e do Oxlint na pasta que está aberta. Com a pasta do projeto aberta como principal, tudo encontra as configurações certas, e o terminal já abre no lugar certo.

Instalar as dependências

Na janela nova, abra o terminal (Ctrl + ') e digite:

npm install
O projeto veio só com a lista do que precisa, no arquivo package.json. O npm install lê essa lista e baixa tudo para a pasta node_modules: o React, o TypeScript, o Vite e o Oxlint, cerca de 100 MB. Também cria o package-lock.json, que anota a versão exata de cada pacote instalado, para que o projeto funcione igual em qualquer computador. A pasta node_modules nunca é copiada nem enviada para ninguém: quem receber o projeto roda npm install e ela é recriada.
Termina com uma linha parecida com added 28 packages e found 0 vulnerabilities, e aparece a pasta node_modules no painel da esquerda.
Se der erro no passo 3

O comando fica parado muito tempo, ou aparece ETIMEDOUT, ECONNREFUSED ou ENOTFOUND: a rede não está deixando o npm baixar os pacotes. Siga o plano B, rede da empresa.

Aparece SELF_SIGNED_CERT_IN_CHAIN ou UNABLE_TO_GET_ISSUER_CERT_LOCALLY: a rede da empresa inspeciona as conexões com um certificado próprio. Também está no plano B, rede da empresa.

“a execução de scripts foi desabilitada neste sistema”: o terminal ainda é o PowerShell. Refaça a configuração do terminal do passo 2 e abra um terminal novo, no ícone de lixeira e depois no +.

EPERM ou EBUSY: algum programa está segurando arquivos da pasta, geralmente o antivírus ou o OneDrive. Confira se a pasta não está dentro do OneDrive e rode npm install de novo.

Rodei npm install e apareceu ENOENT ... package.json: o terminal não está na pasta do projeto. Veja o caminho escrito antes do cursor: ele precisa terminar em central-de-solicitacoes. Se não terminar, digite cd central-de-solicitacoes.

4Rodar o projeto no Chrome

npm run dev
VITE v8.3.6 ready in 217 ms ➜ Local: http://localhost:5173/ ➜ Network: use --host to expose

Abra http://localhost:5173 no Chrome. Aparece a página de boas-vindas do Vite com React.

npm run dev executa o script dev que está no package.json, e esse script inicia o Vite. localhost quer dizer “este computador”: o servidor roda na sua máquina, e só você o acessa. O 5173 é a porta, um número que identifica esse servidor entre outros programas. Enquanto ele estiver rodando, toda vez que você salvar um arquivo, o Vite atualiza o navegador sozinho, em menos de um segundo.
A página do Vite abre no Chrome. Durante a aula, escreva 1 no chat quando chegar aqui.

Para parar o servidor: clique no terminal e aperte Ctrl + C. Para iniciar de novo, npm run dev. Deixe o terminal aberto enquanto trabalha.

Se der erro no passo 4

A porta é outra, como 5174: a 5173 já estava em uso, talvez por outro terminal com o Vite rodando. Não tem problema: use o endereço que o terminal mostrar.

O Chrome diz “Não é possível acessar esse site”: o servidor não está rodando. Olhe o terminal: se ele voltou para o cursor, rode npm run dev de novo. Se apareceu um erro em vermelho, mande um print no grupo.

Ao clicar no link do terminal, abriu outro navegador: tudo bem. Copie o endereço e cole no Chrome.

5O TypeScript, agora no editor

Na sexta, os erros de tipo apareciam no painel da direita do laboratório. No projeto, eles aparecem em três lugares:

OndeQuando
No editor, sublinhado em vermelho, e no painel Problems (Ctrl + Shift + M)Enquanto você digita. É onde você vai olhar quase sempre.
No terminal, com npm run buildQuando o projeto é preparado para publicação. Se houver erro de tipo, a preparação para e nada é publicado.
No terminal, com npm run lint, e no editor com a extensão OxcAvisos de boas práticas, que não são erros de tipo.
Atenção a uma diferença importante: o npm run dev não confere os tipos. Para ser rápido, o Vite só remove as anotações e entrega o JavaScript ao navegador. Então a página pode abrir mesmo com um erro de tipo. Quem avisa é o editor. Por isso, o hábito é: sublinhado vermelho, pare e corrija.

Uma linha a mais no tsconfig

Abra o arquivo tsconfig.app.json e acrescente "strict": true, logo abaixo de "compilerOptions": {:

{
  "compilerOptions": {
    "strict": true,
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.app.tsbuildinfo",
O modo estrito é o que fez o TypeScript reclamar do null do querySelector na sexta. A versão do TypeScript do projeto já liga esse modo sozinha, mas o VS Code tem a própria versão do TypeScript, que pode ser outra. Escrevendo a configuração, o editor e o projeto seguem a mesma regra, sem depender de versão.

Instalar a extensão Oxc

Aperte Ctrl + Shift + X, procure Oxc, confira que a publicadora é oxc e clique em Install.

No arquivo src/App.tsx, escreva const x: number = "texto" numa linha qualquer: aparece o sublinhado vermelho e um item no painel Problems. Apague a linha e salve com Ctrl + S.

BPlano B

Sem permissão de administrador: Node.js em uma pasta sua

O Node também é distribuído em um arquivo .zip, que não precisa ser instalado.

  1. Em nodejs.org/pt-br/download, com a versão LTS e Windows selecionados, baixe o Binário Independente (.zip) para x64.
  2. Descompacte dentro da sua pasta de usuário. Vai aparecer uma pasta com nome parecido com node-v26.13.0-win-x64. Renomeie para node, ficando C:\Users\seu.nome\node.
  3. Tecla Windows, digite variáveis de ambiente e escolha Editar as variáveis de ambiente para sua conta. Essa opção é só da sua conta e não pede administrador.
  4. Em Variáveis de usuário, selecione Path, clique em Editar, depois em Novo, e cole C:\Users\seu.nome\node, com o seu nome de usuário. Confirme com OK em todas as janelas.
  5. Abra um terminal novo e rode node -v.

Por que funciona: o Path é a lista de pastas onde o Windows procura um programa quando você digita o nome dele. Colocando a pasta do Node ali, os comandos node, npm e npx passam a ser encontrados.

Rede da empresa bloqueando o npm: proxy e certificado

Primeiro, teste se o npm alcança o repositório de pacotes:

npm ping

Se responder PONG, a rede está liberada e o problema é outro: mande um print no grupo. Se der erro, a rede da empresa provavelmente exige um proxy, um intermediário por onde passam as conexões com a internet. O endereço do proxy é fornecido pela TI. Com ele em mãos, rode os dois comandos, trocando ENDERECO:PORTA pelo que a TI informar:

npm config set proxy http://ENDERECO:PORTA
npm config set https-proxy http://ENDERECO:PORTA

Se o erro for de certificado (SELF_SIGNED_CERT_IN_CHAIN ou UNABLE_TO_GET_ISSUER_CERT_LOCALLY), peça à TI o certificado da empresa em formato .pem e aponte o npm para ele:

npm config set cafile C:\Users\seu.nome\certificado-empresa.pem

Não use a sugestão comum na internet npm config set strict-ssl false. Ela desliga a verificação de segurança das conexões, e qualquer pacote adulterado no caminho seria aceito.

Para desfazer, se mudar de rede: npm config delete proxy, npm config delete https-proxy e npm config delete cafile.
