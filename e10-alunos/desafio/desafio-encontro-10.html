Desafio do encontro 10

Opcional. Comece do ponto 4-tentar-de-novo, com a API do curso rodando. A aula de amanhã não depende do desafio.

1. Consultar uma solicitação pelo número

O atendente recebe uma ligação: “quero saber da minha solicitação 26-08830”. Crie um cartão Consultar solicitação, com um campo para o número e um botão Consultar, que pergunta direto à API.

  • No api.ts, uma função buscarSolicitacao(numero) que usa GET /api/solicitacoes/{numero} e devolve Promise<Solicitacao | null>.
  • Quando a API responder 404, a função devolve null: não existir não é uma falha, é uma resposta. Os outros erros continuam lançando um Error.
  • Um componente novo, ConsultaPorNumero, mostra uma de quatro coisas: consultando, o resumo da solicitação, “não existe solicitação com esse número”, ou uma mensagem de falha.

Dica: aqui a busca acontece por causa de um clique, então o lugar dela é a função do evento onSubmit, que pode ser async. Não precisa de useEffect. Teste com 26-08830, com 26-99999 e com a API parada.

2. Atualizar a lista

Acima dos filtros, mostre “Atualizado às 09:42.”, com a hora em que a lista chegou da API, e um botão Atualizar lista, que busca de novo.

Dica: o botão pode reaproveitar o mesmo mecanismo do “Tentar de novo”. Para a hora: new Date().toLocaleTimeString("pt-BR", { hour: "2-digit", minute: "2-digit" }).

Para pensar

No item 1, o 404 vira null. Na lista da aula, qualquer resposta que não seja ok vira erro. Por que a mesma API recebe dois tratamentos diferentes?
