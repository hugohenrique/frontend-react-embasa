Etapa 1 do ciclo

Problema real

A página que funciona.

A demanda

Criar a página onde os colaboradores abrem chamados internos.

  • Funcionar em qualquer navegador
  • Ser usável pelo teclado e por leitor de tela
  • Ser fácil de manter e evoluir

Três colegas vão usar essa página

Ana

Usa o mouse, como a maioria de nós.

Carlos

Navega só pelo teclado. Por causa de uma lesão no punho, evita o mouse.

Marcos

É cego. Usa um leitor de tela, que lê a página em voz alta.

A página só está pronta se funcionar para os três.

Como se navega pelo teclado

Tabvai para o próximo elemento
Shift + Tabvolta para o anterior
Entersegue um link ou aciona um botão
Espaçoaciona um botão ou marca uma opção
Nome

O foco é o contorno que mostra onde você está.

O que é um leitor de tela

Um programa que lê em voz alta o que está na tela. Ele só consegue dizer o que a página informa.

O que nós vemos
Nome
O que o Marcos ouve

“Campo de texto, em branco.”

A frase exata varia de um leitor de tela para outro.

Resultado dos testes

CarlosNão conseguiu

O menu e o botão Enviar nunca recebem o foco.

MarcosNão conseguiu

A página é a mesma para os três.

Então por que ela funciona para a Ana e não para o Carlos e o Marcos?

você digita navegador pede servidor devolve o conteúdo árvore em memória o que se vê

O DOM também gera a árvore de acessibilidade, usada pelos leitores de tela.

A resposta tem um código de status

2xxSucesso. O mais comum é 200.
3xxRedirecionamento para outro endereço
4xxErro de quem pediu. 404: não encontrado
5xxErro no servidor. 500: erro interno

Além do status, a resposta traz cabeçalhos e o corpo, que aqui é o HTML.

Duas regras que resolvem muita coisa

  
Leva a outro lugar? a. Executa uma ação? button.

  
div e span não têm significado. Use quando nada melhor servir.







  
Por que a escolha da tag importa

  

    
Acessibilidade
Leitores de tela saltam entre regiões e títulos.

    
Manutenção
O código diz o que cada parte é.

    
Comportamento pronto
Foco, teclado e envio sem uma linha de JavaScript.

Todo campo precisa de um rótulo

  

  
O for do rótulo aponta para o id do campo. Clicar no rótulo leva ao campo. Placeholder não substitui rótulo.







  
O tipo certo trabalha por você

  

    
emailValida o formato e mostra o @ no teclado do celular

    
telAbre o teclado numérico

    
dateMostra um seletor de data

    
requiredImpede o envio com o campo vazio

  







  
Grupos de opções têm um título

  







  
Para onde vão os dados

  
Cada campo viaja com o seu name. Com method="get", os dados aparecem no endereço:

  
index.html?nome=Ana+Souza&email=ana%40exemplo.com&prioridade=alta

  
Em sistemas reais, dados pessoais não vão no endereço. Na etapa 3, enviaremos para uma API.
